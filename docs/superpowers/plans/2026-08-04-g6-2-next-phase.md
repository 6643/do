# G6.2 Resource Result and Cancellation Follow-Up Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:executing-plans` to implement this plan task-by-task. Steps use checkbox syntax for tracking.

**Goal:** Close the already-approved private `Err(failed)` resource-result terminal slice, then design and (only after approval) implement an explicit Component cancellation source shape without adding public ownership/reference syntax.

**Architecture:** Treat error completion and cancellation as separate gates. The error slice reuses the fixed two-word result buffer and existing task-return/frame cleanup. Cancellation first gets an explicit source-shape and pinned-toolchain probe; implementation is limited to the registered private resource descriptor and follows the existing child-before-parent cleanup contract. No rollback or compensation is inferred from cancellation.

**Tech Stack:** Zig 0.16 compiler/tests, Do WAT/WIT emitter, pinned `wasm-tools 1.254.0`, Rust 2024, Wasmtime `47.0.2`, Bash regression harness.

## Global Constraints

- Preserve the private `do:resource-probe/http@0.1.0` WIT shape: `send: async func(request: request) -> result<response, error-code>`.
- Keep `Result<HttpResponse, HttpError>` internal to the registered descriptor; do not generalize arbitrary resource/list/variant/payload layouts.
- Do not add public `own<T>`, `borrow<T>`, `ref<T>`, pointer, or reference syntax.
- Do not add arbitrary async-call lowering, arbitrary producer expressions, general producer leases, sixth forwarding, or seventh nested-resource depth.
- Cancellation never rolls back an already-issued external effect; it only follows Component task/subtask lifetime and exactly-once cleanup.
- Keep `wasm-tools 1.254.0` and Wasmtime `47.0.2` pinned.
- Preserve unrelated dirty worktree changes; do not reset, clean, checkout, commit, or push as part of this plan.

- [x] **Step 1: Compare the two source-shape options.**

  Evaluate (A) explicit `@cancel(completion)` on a named completion value and (B) implicit cancellation when a completion value leaves scope. Recommend A because it is observable in source, maps to a concrete Component operation, and avoids hidden control-flow/resource effects; retain B as rejected because the current language has no implicit reference/borrow lifetime model.

- [x] **Step 2: Freeze the cancellation contract.**

  The contract must state: cancellation is terminal for the private frame; live Component child task/stream/resource handles are released exactly once; the host future is dropped; already-issued external effects remain untouched; no rollback callback, operation id, or compensation protocol is generated.

- [x] **Step 3: Add the pinned negative and positive probes.**

  The positive probe must exercise a pending completion that is explicitly cancelled and observe future drop plus empty resource state. Negative probes must reject implicit scope-drop cancellation, double cancellation, cancellation after terminal completion, and cancellation of an unrelated arbitrary async call.
