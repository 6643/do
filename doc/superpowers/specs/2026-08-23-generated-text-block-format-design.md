# Generated Text Block Formatting Design

## Status

Approved for implementation. This is a source-level formatting refactor for
structured text emitted by the toolchain. It must preserve generated bytes.

## Goal

Use one shared helper for multiline structured text emitted by the compiler,
WIT emitter, Do-source emitter, Component metadata generator, and probe
generators. The helper removes incidental common indentation, applies an
explicit base indentation, preserves relative indentation, blank lines, and
trailing newlines, and supports named `std.fmt` arguments.

## API

Create `src/build/codegen_text.zig` with these public functions:

Single-line generated fragments use the ordinary formatting helpers. They keep
the generated instruction on one logical line; a terminating `\n` is part of
that line and is not a reason to use a block helper.

```zig
pub fn append_fmt(
    allocator: std.mem.Allocator,
    out: *std.ArrayList(u8),
    comptime format: []const u8,
    args: anytype,
) !void

pub fn alloc_fmt(
    allocator: std.mem.Allocator,
    comptime format: []const u8,
    args: anytype,
) ![]u8
```

Structured output containing two or more generated lines uses the block
helpers:

```zig
pub fn append_block(
    allocator: std.mem.Allocator,
    out: *std.ArrayList(u8),
    base_indent: usize,
    template: []const u8,
) !void

pub fn append_fmt_block(
    allocator: std.mem.Allocator,
    out: *std.ArrayList(u8),
    base_indent: usize,
    comptime format: []const u8,
    args: anytype,
) !void

pub fn alloc_block(
    allocator: std.mem.Allocator,
    base_indent: usize,
    template: []const u8,
) ![]u8

pub fn alloc_fmt_block(
    allocator: std.mem.Allocator,
    base_indent: usize,
    comptime format: []const u8,
    args: anytype,
) ![]u8
```

`append_fmt_block` formats with `std.fmt.allocPrint` and then applies exactly
the same block normalization as `append_block`. Named placeholders use the
standard Zig form, for example `{[offset]d}` with `.{ .offset = value }`.

Generated-text format arguments are always named; positional forms such as
`{s}`/`{d}` with `.{ value }` are not part of this API contract. The shared
format helpers enforce this at compile time: a non-empty positional tuple is
rejected, while an explicitly empty tuple remains valid for a format with no
arguments. For example, the single-line form is:

```zig
try generated_text.append_fmt(
    allocator,
    out,
    "    local.get ${[name]s}\n",
    .{ .name = STORAGE_PUT_SOURCE_TMP_LOCAL },
);
```

The equivalent multi-line form is selected only when the generated output has
multiple instructions:

```zig
try generated_text.append_fmt_block(allocator, out, 4,
    \\local.get $__cabi_ptr
    \\local.get $__copy_bytes
    \\i32.const {[stride]d}
    \\
, .{ .stride = stride });
```

Using a raw `\\` template for one generated line adds no semantic value and
must be replaced by `append_fmt` (or `appendSlice` when no formatting is
needed).

The WIT-to-Do emitter's generated header is an intentional two-line block
(header plus a blank separator), so it uses `append_block`; a single emitted
instruction with only its terminating newline remains a single-line helper
call.

## Normalization Contract

1. Split on LF while retaining every LF in the output.
2. Treat only ASCII spaces as indentation. Tabs and other bytes are content.
3. Find the smallest leading-space count among non-empty lines.
4. Remove that common count from each non-empty line.
5. Prefix `base_indent` ASCII spaces to each non-empty line.
6. Emit blank lines without base indentation.
7. Preserve an initial newline, final newline, and all non-indentation bytes.
8. An empty template emits no bytes.

The helper does not infer semantic nesting. Relative indentation after common
indent removal is preserved exactly.

## Scope Boundary

Included: compiler-generated WAT, WIT, Do source, Component metadata, and
test/probe source text assembled from structured templates.

Excluded: user-provided source text, diagnostics and human-facing messages,
JSON/LSP/protocol payloads whose escaping or byte layout is an ABI contract,
single-line fragments, and data copied without structural formatting.

## Compatibility and Verification

This change must not alter generated output. Existing compiler, WIT, Component,
probe, and release tests remain authoritative. The helper gets direct unit
tests for empty input, common indentation, base indentation, nested relative
indentation, blank lines, initial/final newlines, tabs, and named formatting.
