# G6.2 Payload Error ABI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:executing-plans` for inline execution or `superpowers:subagent-driven-development` for task-by-task delegation. Execute the checkboxes in order and stop at the first unmet gate.

**Goal:** Establish a reproducible pinned Component probe for payload-bearing `wasi:http` errors, preserve the current explicit trap boundary while it is blocked, and admit only ABI shapes that pass exact payload-lift and runtime gates.

**Status:** Superseded as an execution checklist by
`2026-08-04-g6-2-payload-error-next-phase.md`. The pinned probe and bounded
two-variant lowering results are retained here as historical design evidence;
the current completion state and residual cancellation boundary are recorded in
the successor plan.

**Architecture:** The first phase is independent of the Do compiler: a pinned full-WIT package, hand-authored Core WAT candidates, and a Rust/Wasmtime runner characterize task-return lift. The compiler remains unchanged while the probe is blocked. If a single payload mapping passes, lowering is added descriptor-first in two bounded increments: `internal-error(option<string>)`, then `DNS-error(DNS-error-payload)`.

**Tech Stack:** Zig compiler and WAT emitter, pinned `wasm-tools 1.254.0`, Wasmtime `47.0.2`, Rust `wasmtime` component bindgen, Bash regression harness, pinned WIT at `src/build/p3_wit/wasi-http-0.3.0-rc-2025-09-16`.

## Global Constraints

- Keep `wasm-tools 1.254.0 (bb58fdf91 2026-07-20)` and Wasmtime `47.0.2` unchanged for this gate.
- The full pinned `wasi:http/types.error-code` definition is authoritative; do not use a shortened variant as evidence for the real HTTP task-return shape.
- The probe must identify one exact payload mapping; a candidate that traps or changes `Some` to `None` is rejected even if another candidate avoids a trap.
- Until the probe is green, keep the HTTP emitter's explicit `unreachable` guards for every registered payload-bearing error tag.
- Do not add public `own<T>`, `borrow<T>`, `ref<T>`, pointer, or reference syntax.
- Do not add general producer leases, borrowed resources, arbitrary stream sources, scheduler work, or real D2 host integration.
- Cancellation keeps the existing no-rollback semantics and exactly-once cleanup contract.
- Preserve all unrelated dirty worktree changes; stage only files belonging to the current task.

### Task 2: Implement the Rust/Wasmtime observation runner

**Files:**

**Interfaces:**
- Consumes: a component path and a mode (`canonical` or `host-lowered`).
- Produces: one machine-checkable line per case:
  `payload-gate=<blocked|green> case=<name> observation=<value>`.

- [ ] **Step 1: Add the exact Rust payload types.**

Reuse the complete `DnsErrorPayload`, `TlsAlertReceivedPayload`,
`FieldSizePayload`, and `ErrorCode` definitions already proven in
`examples/p3-runtime/rust-host-runner/src/bin/http_response_consume_body.rs`
(the enum includes every pinned case, not only the three payload cases).
The payload arms that the new runner must exercise are:

```rust
let dns_error = ErrorCode::DnsError(DnsErrorPayload {
    rcode: Some("EAI".to_owned()),
    info_code: Some(7),
});
let internal_error = ErrorCode::InternalError(Some("x".to_owned()));
```

The actual runner uses the full `ErrorCode` enum copied from that existing
file.  The bindgen world must be the pinned package's `service` world.  Do not
use a shortened WIT package or a three-case custom enum for the runner.

- [ ] **Step 2: Install the host resources and controlled `client.send`.**

Register `request` and `response` resource drops in a `ResourceTable`, consume
each request exactly once, and return the selected error case from the async
host function.  The runner must execute two calls in one Store: one
no-payload `DnsTimeout` control and one selected payload case.  The host
function returns a typed value for the host-lowered candidate; the canonical
candidate is driven by the hand-authored Core callback.

The runner must print and assert these observations:

```text
control=DNS-timeout observation=Err(DNS-timeout)
payload=internal-error(None) observation=InternalError(None)
payload=internal-error(Some("x")) observation=InternalError(Some("x"))
payload=DNS-error observation=DNS-error(rcode=Some("EAI"),info-code=Some(7))
table-empty=true
```

If Wasmtime traps inside task-return lift, print `observation=trap:<message>`
and return the explicit blocked status.  If a host-lowered candidate produces
`InternalError(None)` for the `Some("x")` input, print the mismatch and return
the blocked status; never normalize it to a passing `None` case.

- [ ] **Step 3: Register the binary and compile it.**

Add this exact Cargo entry:

```toml

```

Run:

```bash

```

Expected: pass with the pinned lockfile and no changes to dependency versions.

- [ ] **Step 4: Finish the script's two status modes.**

The default script runs the control and both payload candidates.  With the
current toolchain it must report the known blocker, for example:


It must exit nonzero for an unexpected trap in the no-payload control,

```zig
pub const ErrorVariantFieldKind = enum {
    optional_string,
    optional_u16,
};
```
